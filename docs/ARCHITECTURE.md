# 系统结构说明

## 主入口

`fund_platform.py` 是唯一主程序入口，包含：

- 原基金筛选系统
- 桌面可视化系统
- 内置结果查看器
- 策略差异化结果看板
- 基金详情和交互走势图
- 一键运行流水线
- 迭代爬虫补丁
- 低内存流式评分计算
- 独立进程模块计算
- SQLite 基金详情索引
- 模块缓存
- 市场首页和资金流
- 我的持仓模块

## 运行时目录

程序运行后会在主程序同级目录生成运行数据：

```text
fund_data/             基金 JSON 数据
fund_excel/            评分和筛选 Excel
fund_cache/            模块缓存、资金流缓存
fund_visual_reports/   可视化报告
target_funds.json      清洗后的基金池
```

这些目录不属于开源代码，默认不上传 GitHub。

## 模块关系

```text
一键运行
  -> 智能清洗
  -> 迭代爬取
  -> 模块预计算
  -> 缓存结果
  -> 软件内可视化展示

模块按钮
  -> 优先读取缓存
  -> 无缓存则提交后台任务
  -> 独立 Python 子进程执行重计算
  -> 完成后回到主界面打开结果
  -> 按策略类型选择核心指标
  -> 内置表格/图表/详情/对比展示

基金详情
  -> 优先按基金代码读取 SQLite 本地索引
  -> 区间切换
  -> 最大回撤/修复状态叠加到走势图
  -> 十字线查看日期、净值和涨跌

我的持仓
  -> 导入 CSV/Excel
  -> 按代码读取 SQLite 索引
  -> 计算市值/盈亏/今日收益
```

## 性能设计

- UI 线程只负责 Tkinter 渲染和用户交互。
- 大 JSON 不在点击详情时整文件加载，而是生成 `fund_cache/fund_index.sqlite` 后按基金代码读取。
- 模块重计算通过 `--run-module` 独立子进程执行，主程序只接收日志和结果路径。
- 模块并发数默认最多 2 个，可通过环境变量 `FUND_MODULE_WORKERS` 调整到 1-4。
- 结果表格采用分批插入，避免一次性插入大量 Treeview 行导致窗口未响应。
- 净值走势图按画布宽度降采样绘制，十字线仍对应完整历史数据。

## 设计原则

- 数据和代码分离。
- 本地数据不上传。
- 结果优先走软件内展示。
- 日常更新采用增量迭代，避免重复爬取全部历史。
- 首次完整历史可单独补全，后续只补最新净值。
